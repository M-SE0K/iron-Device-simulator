Render Bench — Canvas2D 렌더링 엔진/하드웨어 수치 비교

같은 파일을 macOS Safari(= WKWebView 엔진)와 Windows Edge(= WebView2 엔진)에서 열고 "전체 실행"을 누른 뒤, 하단 "결과 JSON 복사"로 두 결과를 비교하세요. 측정 중에는 창을 전면에 두고 다른 작업을 하지 마세요(백그라운드 탭은 rAF가 스로틀됩니다).

0. 환경

1. 프레임 케이던스 (idle rAF — "정지 상태 버벅임" 판정)

아무것도 그리지 않고 rAF 간격만 측정. median이 화면 주기(60Hz≈16.7ms)와 다르거나 p95가 크게 튀면 그리기 비용과 무관한 환경 문제(전원 모드/주사율/합성기).

2. 엔진 마이크로벤치 (redraw 1회의 원가)

uPlot 리드로우 1회를 모사: clearRect + Path2D polyline stroke. 900×300 CSS px, DPR 반영.
submit = CPU 측 명령 제출 비용(경로 생성·Skia/CG 기록), flush = 1px readback으로 래스터까지 강제 동기화한 비용.
→ 점 수를 늘릴 때 submit이 비례해서 커지면 CPU 병목(외장 GPU로 해결 불가), 캔버스 크기를 키울 때 flush만 커지면 GPU/래스터 병목.

3. 중복 증폭 효과 (차트 수 K × 프레임당 리드로우 R)

실제 대시보드처럼 캔버스 K개를 화면에 두고, 매 rAF마다 각 캔버스를 R회 전체 리드로우(클리어+정적 레이어 drawImage+라이브 폴리라인 stroke). 4초간 실제 프레임 간격을 기록 — jank% = 기대 주기의 1.5배를 넘긴 프레임 비율. R이 1→3으로 갈 때 jank%가 뛰는 지점이 그 머신의 예산 한계.
